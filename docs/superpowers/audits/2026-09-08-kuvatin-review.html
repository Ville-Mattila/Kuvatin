66 findings at v2.6.0 — one compliance gap, then craftsmanship.

Five parallel reviewers — image engine, video engine, GUI, Explorer/CLI/headless paths, and installer/CI/site/licensing — each verifying claims in source before reporting; the top findings were re-verified by hand and are marked where two reviewers converged independently. Health scorecard

Kuvatin has grown from an image batch tool into a small video editor in three months, and it shows in the good way — the hard GStreamer lessons are pinned by regression tests, the headless paths finally have feedback and cancellation, and releases are pinned and (now) cache-warm. It also shows in the predictable way: the GUI file is twice the size the last audit flagged, five copies of the "what is an image" list disagree, and the installer has quietly become a redistributor of 390 third-party binaries without carrying their licenses.

AreaAssessment
kuvatin-core (images)BCareful arithmetic, panic isolation, atomic output reservation — all tested. Two shipped-path bugs undercut its two promises: folder-mode Convert can silently overwrite same-named inputs from different folders, and a crop drawn on an EXIF-rotated photo lands on the wrong region. The default preset can hard-fail on noisy photos.
kuvatin-video (engine)BMature where it hurt before (commit deadlocks, NVENC caps, stride). Missing: a state guard around render mode (transport keys reach the rendering pipeline), %-escaping in image-sequence patterns (a printf-format injection), and any hygiene for the EXR conversion cache on the right-click path.
kuvatin (GUI)C+Disciplined wiring and the hardening plan landed — but export start blocks the UI for seconds, a failed video-engine init is a silent no-op forever, an unreadable file leaves Crop aimed at the previous image, there is zero accessibility, and run() is ~1,650 lines with 35 closures.
Explorer / CLI / headlessB−The rendezvous and progress window are sound and tested. But every GUI launch re-points the installed menu at whatever exe is running, the menu cannot show user presets while the website says it does, .jfif gets the menu and then "no image files", and errors before the progress window exist stay silent.
Installer / CI / site / legalD+SHA-pinned downloads, a tag-version guard, and a fixed cache scope are genuinely good. The MSI, however, ships ~390 LGPL/GPL/BSD DLLs with no license texts or notices, ~60 MB of unused and patent-encumbered codecs, is unsigned, and the video engine still never gates a release.

§0
C1shipThe MSI redistributes ~390 third-party DLLs with no license texts, notices or source offer

The harvest copies bin\*.dll (130) and lib\gstreamer-1.0\*.dll (261) and nothing else; the only license the installer places is Kuvatin's own License.rtf. Those DLLs include LGPL-2.1 (GStreamer, the FFmpeg build), GPL-2.0-or-later (x264, x265, a52dec, libdca) and BSD/MPL/Apache components whose licenses require the text and copyright notices to accompany the binaries — and, for the (L)GPL ones, an offer of corresponding source. Upstream already provides all of it: share\licenses\ holds 82 component directories (verified: x264\GPL-2.0-or-later.txt, ffmpeg\README-LICENSE-INFO.txt). Kuvatin being GPL-3 makes the combination compatible; it does not remove the notice obligations.

Fix: harvest share\licenses\ into [APPLICATIONFOLDER]\licenses in bundle-gstreamer.ps1; add a THIRD-PARTY-NOTICES file; state the GStreamer 1.26.11 source URLs in README and the release template. cargo deny (M28) then keeps the Rust side honest too.

H1coregui×2Folder-mode Convert silently overwrites same-named inputs from different folders

Outputs are planned with ensure_unique, which only asks the filesystem whether a name is taken — not the other targets in the same batch. Drop A\IMG_0001.jpg and B\IMG_0001.jpg with an output folder chosen and both plan IMG_0001-kuvatin.webp; process_file_to then writes with plain fs::write, so one result vanishes while both rows read "done". plan_unique_outputs was written for exactly this and is referenced only by its own test.

Fix: route the GUI's folder mode through plan_unique_outputs (or write_unique's create_new reservation); delete ensure_unique as an output planner.
kuvatin/src/gui.rs:772–778 · kuvatin-core/src/naming.rs:79 · pipeline.rs:339, 351
§1
H2coreguiCrop rectangles ignore EXIF orientation — the preview and the pipeline see different pixels

The viewer and thumbnails decode with plain image::open (no rotation) and store the crop in that pixel space; process_file decodes via the private decode_oriented, rotates, and then clamps the same rectangle against swapped dimensions. On a portrait phone photo the user crops one region and gets another.

Fix: make decode_oriented public and use it for the preview and thumbnails, so what you crop is what gets cropped.

H3videoguiNo render-mode guard: Space or Delete during an export hits the rendering pipeline

Project has no notion of "rendering"; play/pause/seek/remove_clip go straight to the pipeline. The export modal swallows clicks, but the keyboard FocusScope is gated only on Videos mode — Space calls pause() on the render pipeline (the export freezes until the watchdog says "stuck"), Delete removes a clip and commits mid-render.

H4video% in a frame file name is printf-format-injected into imagesequencesrc

pattern_name() copies prefix and suffix verbatim into the printf pattern GStreamer feeds g_strdup_printf. 50%_off_0001.png becomes 50%_off_%04d.png (wrong file names); take%s_0001.png hands %s an integer — undefined behaviour in native code. Detection succeeds (Rust format! is literal), so the failure only surfaces inside GStreamer.

Fix: escape % → %% in prefix and suffix inside pattern_name(); add the unit test.

§3
H10shellThe shell association and the engine's extension gate disagree

The verb sits on SystemFileAssociations\image — Windows' PerceivedType set, which includes .jfif/.jpe/.dib/.ico/.wmf/.emf (and .webp/.heic/.avif when codec packs are present) — yet IMAGE_EXTS rejects .jfif, so the menu appears and then reports "no image files in selection". Conversely .exr has no PerceivedType, so "Render image sequence to MP4" never appears on an EXR frame — only via its folder.

Fix: register per extension (SystemFileAssociations\.exr\shell\…) for the supported set, and accept .jfif/.jpe; see M34 for the single source of truth.

H11shipThe bundle ships patent-encumbered and unused codecs — roughly 60 MB of dead weight

Systemic themes

Four patterns account for most of the list. Fixing the pattern is cheaper than fixing the instances.

Two paths, one lesson learned

The headless path learned things the GUI path didn't (size normalisation, the stall watchdog baseline, the 10-item error cap) and vice versa (error dialogs, cancellation types). H6, M7, M11, M12, M23 are all "port the fix to the other side". A shared ExportSettings::normalized() and one failure-summary helper close most of it.

Silence is still the default failure mode

The last audit's headline was "errors are invisible"; the shipped build is far better, but new silent paths appeared with each feature: engine init (H5), run_with_progress errors (M12), --register (M17), end_render (L15), unreadable selections (H7). A rule of thumb worth enforcing in review: every let _ = and every eprintln! in the GUI crate needs a justification comment.

%TEMP% is a database now

Rendezvous spool, EXR cache, render fixtures — all live under %TEMP%\kuvatin with different lifetimes and no owner (M9, L9). Give it one module with create/claim/sweep semantics and a byte budget, and call sweep from every entry point.

Growth without structure

gui.rs and app.slint absorb every feature as another closure and another modal (M35, L13, L12), and five extension lists (M34) exist because there is no obvious home for the concept. The split proposed in M35 is the single highest-leverage refactor: it makes the next ten features cheaper and most GUI findings testable.

Suggested plan

Ordered by risk to users and to the project, not by effort. §0 is a compliance fix and should ship in the next release regardless of anything else; §1 protects users' files; the rest can flow release by release.

What's good — and worth protecting

  • The engine learned from its scars. Async commits (the deadlock), fully pinned encode caps (the NVENC renegotiation death), the mfaacenc derank with its root-cause note, stride-aware frame extraction, i128 trim math with the wrap regression pinned — each a real production bug turned into a test.
  • Data safety primitives exist and are tested. write_unique's create_new reservation is verified by an actual racing test; panicking codecs are isolated per file; quality is clamped at one choke point; the preset store degrades to built-ins with a .bad backup.
  • The headless work is careful. The rendezvous (create-new lock, atomic-rename claims, release-then-sweep) has an eight-thread burst test; the progress window has a grace period, coalesced updates, a panic-isolated worker and a cancel that waits for real completion.
  • Releases are pinned and honest. Every third-party download and every action is SHA-pinned with fail-on-mismatch; the tag-vs-Cargo guard prevents mislabeled installers; the license metadata agrees end to end; and the cache-scope fix took the release run from ~18 to ~9½ minutes.
  • The Slint work is disciplined. Model-pinned hit areas with a separate moving visual, pointer-cancel resets, a window-level drop banner, one track-h source of truth, and honest reduced-motion / no-JS fallbacks on the site.
